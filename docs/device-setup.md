## 로그 저장 (매 세션)
- [ ] Chrome 설정 → 다운로드 → "다운로드 전에 각 파일의 저장 위치 확인" **끔**
- [ ] 첫 다운로드 때 "여러 파일 다운로드" 허용 팝업이 뜨면 **허용**
- [ ] 세션이 끝나면 다운로드 폴더의 파일 개수를 확인한다 (`build` `exp-2026-11-21` 기준, 세션당 **35개**)
  - `events_*.csv`: 블록이 끝날 때마다 1개. 조건당 연습 1 + 본과제 5 = 6개, 세션당 18개
  - `script_*.csv`: 조건이 끝날 때 본과제 제시문 5개, 세션당 15개
  - `session_*.csv`, `participant_*.csv`: 세션 끝에 1개씩
- [ ] 빠진 `events` 파일은 끝 화면의 "브라우저에 백업된 블록" 목록에서 다시 받을 수 있지만, **백업은 브라우저 저장 한도(약 5MB) 때문에 앞쪽 3~4블록만 남는다** (11/20 파일럿). 백업을 믿지 말고 블록마다 다운로드가 됐는지 진행 중에 확인한다
- [ ] 분석 담당(정원준)이 있으면 바로 정리·점검한다: `analysis` 폴더에서 `..\.venv\Scripts\python collect.py <다운로드 폴더>` → `..\.venv\Scripts\python validate_log.py ..\data\raw`. 오류가 나오면 다음 참가자 전에 원인을 확인한다 (README "분석" 참고)
- [ ] 받은 파일은 팀 구글 드라이브로 옮긴다. **저장소에는 올리지 않는다**
- [ ] 다음 참가자 전에, 파일이 드라이브에 다 있는지 확인한 뒤 브라우저 백업을 지운다 (F12 → Application → Local storage → 사이트 주소 → `count-tune-log:`로 시작하는 항목 삭제). 백업이 쌓이면 브라우저 저장 용량이 차서 다음 백업이 실패할 수 있다
